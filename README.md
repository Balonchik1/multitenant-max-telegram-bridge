# MAX ↔ Telegram Bridge

Самостоятельный (self-service) мультитенантный мост между мессенджером [MAX](https://max.ru) и Telegram.

Каждый диалог и группа из MAX получают свою тему в Telegram-супергруппе (форум). Сообщения, медиа, правки и реакции идут в обе стороны, а удаление в MAX отмечается в Telegram. Любой человек может написать боту и привязать свой собственный MAX-аккаунт, получив свою отдельную отражённую группу, полностью изолированную от данных остальных.

Это **не** альтернативный клиент MAX (как [Komet](https://github.com/KometTeam/Komet) или [WhiteMAX](https://github.com/WhiteMAX-Mod/whitemaxmod)) — он входит в реальный MAX-аккаунт в фоне (через неофициальную библиотеку [pymax](https://pypi.org/project/maxapi-python/)) и пересылает сообщения, а не заменяет собой официальное приложение.

## Возможности

- **Обе стороны**: текст, фото, видео, голосовые, аудио, документы, стикеры, ссылки, альбомы, ответы, пересылки (с указанием автора), правки, опросы, контакты, записи о звонках; удаление сообщения в MAX отмечается в Telegram, обратно удаление не передаётся
- **Реакции**: отражаются в обе стороны. MAX не всегда шлёт push-событие об изменении реакции, поэтому направление MAX → Telegram опирается на периодический опрос
- **Мультитенантность**: любой человек может войти в свой MAX-аккаунт и привязать свою Telegram-группу — полностью через переписку с ботом, без доступа к серверу
- **Алиасы и упоминания**: можно дать контакту MAX короткую метку вместо id; ключевое слово в сообщении MAX превращается в настоящее упоминание в Telegram
- **Устойчивость**: добор пропущенных сообщений при переподключении (с защитой по временной границе, а не просто "есть ли уже в базе" — история MAX отдаёт реальную переписку, а не только то, что реально пропущено), повторные попытки и автопересоздание темы, если её удалили в Telegram, очередь отправки с учётом ограничений Telegram по частоте
- **Опциональные зашифрованные бэкапы сессии** — см. раздел «Заметки по безопасности»

## Как это работает

Админ (ты) запускает один процесс. Он держит:
- твой собственный вход в MAX + Telegram-бота
- по одному входу в MAX на каждого подключившегося пользователя, у каждого своя SQLite-база и своя кэш-директория

Пользователь никогда напрямую не трогает твой сервер — он общается только с Telegram-ботом, который проводит его через вход в MAX (номер телефона + SMS-код, и облачный пароль, если MAX его потребует) и привязку Telegram-группы, которой он управляет.

По умолчанию регистрация закрыта: незнакомый человек сначала читает объяснение и нажимает «Отправить заявку», после этого тебе (админу) приходит заявка с кнопками «Разрешить» и «Отклонить», и только после «Разрешить» бот запускает ему вход в MAX. Это защищает сервер и твою репутацию, если ссылка на бота окажется у посторонних. Если нужна открытая регистрация (любой, кто написал боту, сразу идёт на вход), задай `REQUIRE_APPROVAL=false` в `.env`: тогда реальным контролем доступа остаётся то, что ссылку на бота знают только те, кому ты её дал, а о каждом новом пользователе ты просто получаешь уведомление и можешь забанить через `/deny`.

## Требования

- Python 3.12+
- Токен Telegram-бота ([@BotFather](https://t.me/BotFather))
- MAX-аккаунт (номер телефона), как минимум свой собственный

## Установка

```bash
git clone <этот репозиторий>
cd <этот репозиторий>
python3 -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# отредактируй .env — см. ниже
```

### Конфигурация

Вся конфигурация — в `.env` (никогда не коммить этот файл — полный список переменных с описанием в `.env.example`). Минимально нужны:

| Переменная | Обязательна | Описание |
|---|---|---|
| `TG_TOKEN` | да | Токен Telegram-бота |
| `TG_GROUP_ID` | да | Твоя основная Telegram-супергруппа (с включёнными Темами) |
| `TG_GROUP_FLAT` | да | Вторая группа без тем, для одного "плоского" MAX-чата (может быть той же небольшой группой, если эта функция не нужна) |
| `FLAT_MAX_CHAT_ID` | да | MAX-чат, отражаемый в `TG_GROUP_FLAT` |
| `ADMIN_ID` | да | Твой Telegram user id |
| `MAX_PHONE` | да | Номер телефона твоего MAX-аккаунта |
| `REQUIRE_APPROVAL` | нет | Нужно ли твоё подтверждение для новых пользователей. По умолчанию `true`; `false` открывает регистрацию для всех, кто написал боту |
| `MAX_2FA_PASSWORD` | нет | Пропускает запрос пароля при твоём собственном входе, если в MAX включён облачный пароль |
| `SESSION_BACKUP_KEY` | нет | Включает ежедневные зашифрованные бэкапы данных сессии — см. ниже |

### Запуск

```bash
python3 bridge.py
```

Или как systemd-сервис:

```ini
[Unit]
Description=MAX Telegram Bridge
After=network.target

[Service]
WorkingDirectory=/path/to/repo
ExecStart=/path/to/repo/venv/bin/python3 /path/to/repo/bridge.py
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

При первом запуске напиши боту `/start`, чтобы войти в свой собственный MAX-аккаунт (номер телефона, затем SMS-код от MAX).

**Если MAX завершил сессию основного аккаунта.** Так бывает, например, если давно не заходить в приложение MAX. Бот сам больше не заказывает SMS-коды (иначе он засыпал бы телефон и мог получить блокировку входа по номеру): он один раз пишет тебе об этом и оставляет основной аккаунт отключённым, а подключённые пользователи продолжают работать. Чтобы войти заново, пришли боту в личные сообщения `/relogin`: бот перезапустится, закажет один SMS-код и попросит прислать его. На первом запуске (когда вход ещё ни разу не удавался) всё работает как раньше.

**Описание бота.** Чтобы человек, который открыл бота впервые, понимал, что это и зачем, задай описание в [@BotFather](https://t.me/BotFather): `/mybots` → твой бот → Edit Bot → Edit Description. Его видно над кнопкой Start до первого сообщения. Подойдёт, например, такой текст: «Бот пересылает сообщения между MAX и Telegram в обе стороны. Технически для этого нужен полный доступ к аккаунту MAX, поэтому рекомендую подключать аккаунт без важной переписки и без привязанных Госуслуг. Доступ можно отозвать в любой момент». Кроме того, при первом `/start` бот сам показывает такое же объяснение с кнопкой «Отправить заявку».

## Использование

### Команды администратора

Доступны только тебе (`ADMIN_ID`).

| Команда | Описание |
|---|---|
| `/groups` | Список твоих собственных привязанных групп — актуально, если ведёшь больше одной своей группы через `/addgroup` (у обычного пользователя всегда ровно одна группа, и этой команды у него нет) |
| `/addgroup`, `/delgroup` | Управление своими отражёнными группами |
| `/bind <max_chat_id>` | Вручную привязать тему к MAX-чату |
| `/alias <id> <метка>` | Дать контакту MAX короткую метку вместо id |
| `/ping <слово>` | Ключевое слово, которое становится настоящим упоминанием тебя при появлении в сообщении из MAX |
| `/link` | Управление связками `@username` ↔ id MAX для упоминаний |
| `/chats` | Список MAX-чатов, видимых твоему аккаунту |
| `/access` | Список всех, кто писал боту, со статусом |
| `/allow <id>`, `/deny <id>` | Разрешить или отклонить пользователя по id, то же самое делают кнопки в заявке. Удобно, если заявка потерялась или нужно забанить человека позже. `/deny` для уже подключённого пользователя ещё и отключает его мост: бот завершает сессию в MAX и удаляет данные входа с сервера |
| `/senders` | Писать боту в личку. Кто из участников группы может писать в MAX от твоего имени: по умолчанию только ты, можно разрешить отдельным людям или всем (см. ниже) |
| `/info` | Повторно опубликовать инструкцию в #General |
| `/relogin` | Заново войти в основной аккаунт MAX, если MAX завершил его сессию: разрешает один заказ SMS-кода и перезапускает бота |
| `/update` | Обновить `pymax` и перезапуститься (с двойным подтверждением) |

### Команды пользователя (после `/start`)

| Команда | Описание |
|---|---|
| `/start` | Начать — ввести номер телефона MAX |
| `/setupgroup` | Привязать созданную Telegram-группу, где бот назначен админом |
| `/ping <слово>` | То же, что и у админа, но в рамках своих данных |
| `/alias <id> <метка>` | То же, что и у админа, но в рамках своих данных |
| `/retry` | Переподключиться к MAX без нового входа — нужен в нескольких случаях: MAX потребовал включить облачный пароль (2FA), прошлая попытка входа не удалась, вход выполнен но группа ещё не привязана (например бот тем временем перезапускался), или просто оборвалась связь у уже полностью настроенного аккаунта. Также нужен, если MAX завершил вход аккаунта (например, давно не заходили в приложение MAX): бот сам SMS не заказывает, а пишет об этом; после `/retry` приходит один SMS-код, и мост восстанавливается без повторной настройки группы |
| `/logout` | Отключить свой MAX-аккаунт от моста: бот завершает свою сессию в MAX и удаляет с сервера данные входа и служебную базу. Telegram-группа остаётся, подключиться заново можно через `/start` |
| `/cancel` | Прервать незавершённый вход (бот ждёт SMS-код или пароль, либо вход не удался) и очистить всё, что успело сохраниться; потом можно начать заново через `/start` |
| `/senders` | Писать боту в личку. Кто из участников группы может писать в MAX от твоего имени: по умолчанию только ты, можно разрешить отдельным людям или всем (см. ниже) |
| `/support <текст>` | Написать администратору |
| `/info` | Повторно опубликовать инструкцию в #General |

### Кто может писать в MAX из группы

В MAX всё уходит от лица одного аккаунта: владельца моста. Поэтому по умолчанию бот пересылает из Telegram-группы в MAX только то, что сделал сам владелец: его сообщения, правки и реакции. Если в группе есть кто-то ещё, его действия бот игнорирует, а на сообщение отвечает коротким пояснением (не чаще раза в 10 минут на тему). Когда новый человек пытается написать в первый раз, владельцу приходит личное уведомление с кнопками «Разрешить с именем», «Разрешить без имени» и «Не сейчас» (текст сообщения в уведомление не попадает; не больше пяти уведомлений в час). Само сообщение, которое не ушло, бот не сохраняет и после разрешения не досылает: вместо этого он отвечает в группе на это сообщение («✅ Иван теперь может писать в MAX. Отправьте сообщение ещё раз»), и человеку остаётся написать заново.

Команда `/senders` в личных сообщениях с ботом меняет это двумя способами:

- **Конкретные люди.** Кнопка «Добавить человека» показывает тех, кто недавно пытался написать в группу (Telegram не отдаёт боту список участников, поэтому бот запоминает только тех, кто написал сам: пусть человек напишет в группе, и он появится в списке). После выбора бот спрашивает, добавлять ли имя автора к его сообщениям, и показывает пример, как это будет выглядеть в MAX. Настройку имени можно потом менять для каждого человека отдельно, а самого человека убрать из списка.
- **Все участники.** Сообщения, правки и реакции любого участника группы уходят в MAX от имени владельца. Для этого режима есть общий переключатель имён.

К сообщениям других людей бот по умолчанию добавляет имя автора (жирной строкой над текстом), чтобы в MAX было видно, кто написал; сообщения самого владельца идут без имени. Реакции имени не несут. Имена можно выключить, например, если аккаунтом пользуется семья и в общем чате они не нужны.

Настройки хранятся отдельно для каждого владельца и сбрасываются после `/logout` на «только владелец». Сообщения, отправленные от имени группы (анонимный админ), считаются сообщениями владельца.

## Известные ограничения

- Удаление сообщения на стороне Telegram не удаляет его в MAX (у Telegram Bot API нет события для этого)
- Ответ на альбом отображается прикреплённым к превью альбома, а не к конкретному элементу — ограничение отрисовки клиента Telegram
- Контакт, отправленный из MAX, не содержит номера телефона — `pymax` его не отдаёт
- Часть реакций MAX, которых нет у Telegram (и наоборот), не теряется молча, а заменяется на обычное ❤️
- Голосовые из Telegram приходят в MAX как файл с аудио, а не как голосовое сообщение: MAX не принимает загруженное через `pymax` голосовое как готовое, ни ожидание, ни повторы это не меняют. Звук при этом доходит и проигрывается

## Заметки по безопасности

- **Неофициальный протокол.** Всё держится на `pymax` — реверс-инжиниренной библиотеке, а не официальном API MAX. За время разработки формат протокола MAX уже менялся под ней не раз. Использование любого userbot-подобного клиента несёт риск блокировки аккаунта по условиям использования MAX.
- **Кастодиальность сессий.** Живая MAX-сессия каждого подключившегося пользователя хранится на сервере администратора. Тот, кто управляет ботом, в принципе может получить доступ к любому привязанному аккаунту, пока он подключён. Если разворачиваешь это для других людей — они должны это понимать. Пользователь в любой момент может сам отключиться командой `/logout`: бот завершит сессию на стороне MAX и сотрёт данные входа с сервера (зашифрованные бэкапы, если они включены, хранятся по своему сроку, но сессия в них уже недействительна).
- **`SESSION_BACKUP_KEY`** шифрует резервные копии данных сессии (AES-GCM, ключ через PBKDF2) — это защищает архив бэкапа, если он утечёт куда не следует, а не саму живую сессию, которую работающий процесс обязан читать в открытом виде, пока бот запущен.

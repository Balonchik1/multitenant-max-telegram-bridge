# MAX ↔ Telegram Bridge

Самостоятельный (self-service) мультитенантный мост между мессенджером [MAX](https://max.ru) и Telegram.

Каждый диалог и группа из MAX получают свою тему в Telegram-супергруппе (форум). Сообщения, медиа, правки, удаления и реакции идут в обе стороны. Любой человек может написать боту и привязать свой собственный MAX-аккаунт, получив свою отдельную отражённую группу, полностью изолированную от данных остальных.

Это **не** альтернативный клиент MAX (как [Komet](https://github.com/KometTeam/Komet) или [WhiteMAX](https://github.com/WhiteMAX-Mod/whitemaxmod)) — он входит в реальный MAX-аккаунт в фоне (через неофициальную библиотеку [pymax](https://pypi.org/project/maxapi-python/)) и пересылает сообщения, а не заменяет собой официальное приложение.

## Возможности

- **Обе стороны**: текст, фото, видео, голосовые, аудио, документы, стикеры, ссылки, альбомы, ответы, пересылки (с указанием автора), правки, удаления, опросы, контакты, записи о звонках
- **Реакции**: отражаются в обе стороны. MAX не всегда шлёт push-событие об изменении реакции, поэтому направление MAX → Telegram опирается на периодический опрос
- **Мультитенантность**: любой человек может войти в свой MAX-аккаунт и привязать свою Telegram-группу — полностью через переписку с ботом, без доступа к серверу
- **Алиасы и упоминания**: можно дать контакту MAX короткую метку вместо id; ключевое слово в сообщении MAX превращается в настоящее упоминание в Telegram
- **Устойчивость**: добор пропущенных сообщений при переподключении (с защитой по временной границе, а не просто "есть ли уже в базе" — история MAX отдаёт реальную переписку, а не только то, что реально пропущено), повторные попытки и автопересоздание темы, если её удалили в Telegram, очередь отправки с учётом ограничений Telegram по частоте
- **Опциональные зашифрованные бэкапы сессии** — см. раздел «Заметки по безопасности»

## Как это работает

Админ (ты) запускает один процесс. Он держит:
- твой собственный вход в MAX + Telegram-бота
- по одному входу в MAX на каждого подключившегося пользователя, у каждого своя SQLite-база и своя кэш-директория

Пользователь никогда напрямую не трогает твой сервер — он общается только с Telegram-ботом, который проводит его через вход в MAX (номер телефона + SMS-код, и облачный пароль, если MAX его потребует) и привязку Telegram-группы, которой он управляет.

Бот сам по себе не спрашивает разрешения перед регистрацией — любой, кто напишет ему, сразу проходит на вход. Реальный контроль доступа — это то, что **ссылку на бота знают только те, кому ты её дал**; относись к ней как к приглашению, а не публикуй в открытых местах. Админ всё равно получает уведомление о каждом новом пользователе и может задним числом забанить через `/deny`.

## Требования

- Python 3.12+
- Токен Telegram-бота ([@BotFather](https://t.me/BotFather))
- MAX-аккаунт (номер телефона), как минимум свой собственный

## Установка

```bash
git clone <этот репозиторий>
cd <этот репозиторий>
python3 -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# отредактируй .env — см. ниже
```

### Конфигурация

Вся конфигурация — в `.env` (никогда не коммить этот файл — полный список переменных с описанием в `.env.example`). Минимально нужны:

| Переменная | Обязательна | Описание |
|---|---|---|
| `TG_TOKEN` | да | Токен Telegram-бота |
| `TG_GROUP_ID` | да | Твоя основная Telegram-супергруппа (с включёнными Темами) |
| `TG_GROUP_FLAT` | да | Вторая группа без тем, для одного "плоского" MAX-чата (может быть той же небольшой группой, если эта функция не нужна) |
| `FLAT_MAX_CHAT_ID` | да | MAX-чат, отражаемый в `TG_GROUP_FLAT` |
| `ADMIN_ID` | да | Твой Telegram user id |
| `MAX_PHONE` | да | Номер телефона твоего MAX-аккаунта |
| `MAX_2FA_PASSWORD` | нет | Пропускает запрос пароля при твоём собственном входе, если в MAX включён облачный пароль |
| `SESSION_BACKUP_KEY` | нет | Включает ежедневные зашифрованные бэкапы данных сессии — см. ниже |

### Запуск

```bash
python3 bridge.py
```

Или как systemd-сервис:

```ini
[Unit]
Description=MAX Telegram Bridge
After=network.target

[Service]
WorkingDirectory=/path/to/repo
ExecStart=/path/to/repo/venv/bin/python3 /path/to/repo/bridge.py
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

При первом запуске напиши боту `/start`, чтобы войти в свой собственный MAX-аккаунт (номер телефона, затем SMS-код от MAX).

## Использование

### Команды администратора

Доступны только тебе (`ADMIN_ID`).

| Команда | Описание |
|---|---|
| `/groups` | Список твоих собственных привязанных групп — актуально, если ведёшь больше одной своей группы через `/addgroup` (у обычного пользователя всегда ровно одна группа, и этой команды у него нет) |
| `/addgroup`, `/delgroup` | Управление своими отражёнными группами |
| `/bind <max_chat_id>` | Вручную привязать тему к MAX-чату |
| `/alias <id> <метка>` | Дать контакту MAX короткую метку вместо id |
| `/ping <слово>` | Ключевое слово, которое становится настоящим упоминанием тебя при появлении в сообщении из MAX |
| `/link` | Управление связками `@username` ↔ id MAX для упоминаний |
| `/chats` | Список MAX-чатов, видимых твоему аккаунту |
| `/access` | Список всех, кто писал боту, со статусом |
| `/allow <id>`, `/deny <id>` | Разрешить/забанить конкретного пользователя постфактум — доступ по умолчанию открыт всем, эти команды для ручной модерации, а не для одобрения перед входом |
| `/info` | Повторно опубликовать инструкцию в #General |
| `/update` | Обновить `pymax` и перезапуститься (с двойным подтверждением) |

### Команды пользователя (после `/start`)

| Команда | Описание |
|---|---|
| `/start` | Начать — ввести номер телефона MAX |
| `/setupgroup` | Привязать созданную Telegram-группу, где бот назначен админом |
| `/ping <слово>` | То же, что и у админа, но в рамках своих данных |
| `/alias <id> <метка>` | То же, что и у админа, но в рамках своих данных |
| `/retry` | Переподключиться к MAX без нового входа — нужен в нескольких случаях: MAX потребовал включить облачный пароль (2FA), прошлая попытка входа не удалась, вход выполнен но группа ещё не привязана (например бот тем временем перезапускался), или просто оборвалась связь у уже полностью настроенного аккаунта |
| `/support <текст>` | Написать администратору |
| `/info` | Повторно опубликовать инструкцию в #General |

## Известные ограничения

- Удаление сообщения на стороне Telegram не удаляет его в MAX (у Telegram Bot API нет события для этого)
- Ответ на альбом отображается прикреплённым к превью альбома, а не к конкретному элементу — ограничение отрисовки клиента Telegram
- Контакт, отправленный из MAX, не содержит номера телефона — `pymax` его не отдаёт
- Часть реакций MAX, которых нет у Telegram (и наоборот), не теряется молча, а заменяется на обычное ❤️

## Заметки по безопасности

- **Неофициальный протокол.** Всё держится на `pymax` — реверс-инжиниренной библиотеке, а не официальном API MAX. За время разработки формат протокола MAX уже менялся под ней не раз. Использование любого userbot-подобного клиента несёт риск блокировки аккаунта по условиям использования MAX.
- **Кастодиальность сессий.** Живая MAX-сессия каждого подключившегося пользователя хранится на сервере администратора. Тот, кто управляет ботом, в принципе может получить доступ к любому привязанному аккаунту, пока он подключён. Если разворачиваешь это для других людей — они должны это понимать.
- **`SESSION_BACKUP_KEY`** шифрует резервные копии данных сессии (AES-GCM, ключ через PBKDF2) — это защищает архив бэкапа, если он утечёт куда не следует, а не саму живую сессию, которую работающий процесс обязан читать в открытом виде, пока бот запущен.
